# 4.1. Software Configuration Management

## 4.1.3. Source Code Style Guide & Conventions

Los identificadores del código (clases, métodos, variables, archivos y comentarios técnicos) se escriben en inglés. El texto que ve el usuario de la landing está en español e inglés, porque el sitio es bilingüe. Los mensajes de commit siguen el estándar ya descrito en el punto 4.1.2.

### Java y Spring Boot

El backend se escribe según la Google Java Style Guide (Google, s.f.-a).

* Las clases, las interfaces y los métodos van en PascalCase. Las variables locales y los parámetros van en camelCase. Las constantes van en `UPPER_SNAKE_CASE`.
* Las interfaces de dominio no llevan prefijo decorativo. Los nombres describen el rol: `QuoteCommandService`, `StripeGateway`, `Quote`.
* Cada bounded context conserva las cuatro capas `domain`, `application`, `interfaces` e `infrastructure`. El dominio no depende de Spring ni de JPA.
* Los agregados, las entidades y los value objects viven en `domain/model`. Los comandos y las consultas viven junto a ese modelo.
* Los controladores REST viven en `interfaces/rest`. Los recursos de entrada y salida viven en `interfaces/rest/resources`.
* La persistencia JPA vive en `infrastructure/persistence/jpa`. Las tablas salen en snake_case y en plural mediante `SnakeCaseWithPluralizedTablePhysicalNamingStrategy`.
* Las API públicas y los servicios de aplicación se documentan con comentarios Javadoc.

### HTML de la landing

El marcado sigue la Google HTML/CSS Style Guide (Google, s.f.-b).

* Etiquetas y atributos en minúscula. Los valores de los atributos van entre comillas dobles.
* La página usa regiones semánticas (`header`, `main`, `section`, `footer`).
* Toda imagen informativa lleva `alt`. Los controles de formulario quedan asociados a su etiqueta.
* Los enlaces de idioma y los llamados a la acción tienen un texto visible, no solo un ícono.

### CSS

* La indentación es de 2 espacios.
* Los nombres de clase van en kebab-case. Donde hay pieza y subpieza se usa el patrón bloque y elemento, como en `kairo-marquee__logo`.
* El color de marca es el azul `#1E3A8A`. Sobre fondos oscuros, el acento legible es `#60A5FA`.
* Los identificadores se reservan para anclas de navegación (`#planes`, `#contacto`) y no para pintar componentes.

### JavaScript

* Variables y funciones en camelCase.
* Se declaran con `const` o `let`.
* Cada sentencia cierra con punto y coma.
* Las cadenas visibles pasan por el diccionario de `js/i18n.js` (`data-i18n`), de modo que español e inglés no queden escritos sueltos en la lógica.
* Las funciones con parámetros se documentan con JSDoc.

### Kotlin y Android

La aplicación móvil, cuando se implemente sobre el stack del punto 4.1.1, usará las convenciones de Kotlin: PascalCase para tipos, camelCase para funciones y propiedades, y nombres de paquete en minúscula bajo `com.tuxlogic.shiftiq`. Las pantallas se componen con Material Design 3 y el texto de interfaz sale de recursos, no de cadenas fijas en el código.
