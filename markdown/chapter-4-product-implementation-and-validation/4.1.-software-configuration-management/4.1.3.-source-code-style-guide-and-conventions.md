# 4.1. Software Configuration Management

## 4.1.3. Source Code Style Guide & Conventions

### Java / Spring Boot Conventions
- Strict adherence to the **Google Java Style Guide**.
- CamelCase naming for variables and methods (`processDtcFault()`), PascalCase for classes (`WorkshopAggregateRoot`).
- Hexagonal / DDD Layering rules enforced via Package Structure (`domain`, `application`, `interfaces`, `infrastructure`).

### Frontend & JavaScript/TypeScript Conventions
- ESLint configuration with Airbnb ruleset.
- Clean Code principles (single responsibility functions, explicit variable names).
- Formatting enforced with Prettier via Git `husky` pre-commit hooks.

### Commit Message Standard (Conventional Commits)
- Format: `<type>(<scope>): <short description>`
- Examples: `feat(iam): add user registration REST controller`, `docs(report): update chapter 3 UI wireframes`.
