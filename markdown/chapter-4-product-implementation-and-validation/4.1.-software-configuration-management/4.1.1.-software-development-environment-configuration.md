# 4.1. Software Configuration Management

## 4.1.1. Software Development Environment Configuration

El entorno de desarrollo de ShiftIQ corresponde a los artefactos que el equipo TuxLogic mantiene en la organización de GitHub: la landing page comercial, la plataforma backend y el informe. Las versiones de esta sección salen de esos repositorios y del diagrama de contenedores del capítulo 2.

### Backend Stack & Dependencies

La plataforma vive en [shiftiq-platform](https://github.com/tux-logic/shiftiq-platform). Es una API REST organizada por bounded contexts.

* **Lenguaje:** Java 26
* **Framework:** Spring Boot 4.0.6 (Spring Web MVC, Spring Data JPA, Spring Security, Spring Validation y Spring Mail)
* **Base de datos:** PostgreSQL 16
* **Construcción:** Apache Maven 3.9, mediante el Maven Wrapper del repositorio (`mvnw`)
* **Documentación de la API:** springdoc OpenAPI 3.0.3, publicada en Swagger UI
* **Seguridad e integraciones:** JWT (jjwt 0.12.6), Google OAuth, Stripe Java SDK 28.3.0, correo SMTP y la API de Factos para comprobantes SUNAT
* **Apoyo de código:** Lombok

El código se agrupa en ocho contextos: `iam`, `core`, `fleet`, `inventory`, `operations`, `iot`, `billing` y `shared`. Cada contexto separa `domain`, `application`, `interfaces` e `infrastructure`.

### Web Frontend Stack

La superficie web implementada en esta etapa es la landing page de [Shiftiq-Landing-Page](https://github.com/tux-logic/Shiftiq-Landing-Page). Es un sitio estático y responsive, en español e inglés.

* **Marcado y estilo:** HTML5, CSS3 y JavaScript
* **Interfaz:** Bootstrap 5.3 y Bootstrap Icons
* **Tipografía:** Google Fonts (Outfit)
* **Pie de página:** Matter.js
* **Edición:** Visual Studio Code
* **Vista local:** servidor estático con `npx serve`

El diseño de wireframes y mock-ups de esa landing se concentró en Figma, como queda registrado en el punto 3.1.3.

### Mobile Companion App Stack

La aplicación compañera, definida en el diagrama de contenedores, es nativa de Android y se programa en Kotlin. Las pantallas siguen Material Design 3, porque el uso ocurre en el taller, con poca tolerancia a interfaces densas (Google, s.f.-c). El entorno de esa aplicación es Android Studio. El segmento entrevistado usa sobre todo smartphones Android, así que el primer objetivo de dispositivo es Android.

### Containerization & Local Infrastructure

En local, Docker Compose levanta únicamente PostgreSQL 16 (`postgres:16-alpine`) para la plataforma. La base se llama `shiftiq_db` y la API se conecta por JDBC con las variables `DATABASE_URL`, `DATABASE_PORT`, `DATABASE_NAME`, `DATABASE_USER` y `DATABASE_PASSWORD`.

La imagen de la API se construye con un Dockerfile de dos etapas: Maven sobre Eclipse Temurin 26 para compilar, y el JRE 26 para ejecutar el JAR en el puerto 8080 con el perfil `prod`.
